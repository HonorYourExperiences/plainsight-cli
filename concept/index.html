Concept · working name Plainsight

See what you built.

An AI can write a whole app in a weekend. Plainsight draws that app as a live schematic and explains every part in plain English, so you understand what you shipped before your users find the holes. Nothing is drawn for looks: every box, pipe and sentence links back to the exact lines of code it came from.

The rule everything else follows

Faithful, not flattering

A readable drawing that's wrong is worse than no drawing, because people trust it. Revel's engineers trust their P&ID because every symbol is wired to a real sensor. Plainsight has to earn the same trust from code, however large or tangled it is.

Facts from analysis, words from AI

The AI doesn't decide what exists

Parts, pipes and checks are pulled out by parsers, type checkers and call-graph analysis, the same tools compilers use. The AI only writes the sentences, and each sentence is checked against the facts it claims before it's shown.

Receipts

Every claim links to its source

Click any box, pipe or sentence and you see the exact file and lines behind it. If a statement can't point to code, it doesn't get printed.

Zoom, don't simplify

Complexity becomes levels, not omissions

A huge system is shown like a map: zoom out and streets merge into neighborhoods, but no road is invented or erased. Each level is an exact summary of the one below, with real counts.

Honest unknowns

"Can't tell" is a valid answer

Some code can't be resolved by reading it: addresses built from settings, plugins, reflection. Plainsight draws those dashed and labeled, never guessed, then fills them in from live traffic.

Checked against reality

Live traffic confirms the drawing

Real requests are traced through the app. A pipe that never carries data, or data moving where no pipe is drawn, is flagged as drift between the drawing and the truth.

Full coverage

Nothing quietly left off the sheet

Every file belongs to some part of the drawing, and the title block says so. If something doesn't fit, it's listed as unmapped instead of disappearing.

The problem

Vibe coding makes building easy. Understanding is still hard.

Code you didn't write is code you can't fix.

When something breaks at 2 a.m., "ask the AI again" is the only plan most new builders have. That works until it doesn't.

The dangerous bugs are invisible.

A missing login check or a leaked key doesn't crash anything. The app looks finished. You only learn about it when someone else does.

Reading code is the wrong interface.

A builder needs the shape of the system and what each part does. A drawing and a sentence beat 4,000 lines of TypeScript.

Borrowed from the test stand

What Revel does for hardware, applied to code

Revel lets rocket and reactor teams drop valves, pumps and sensors onto a P&ID diagram, wire it to live data, and watch every run. An app has the same anatomy: parts, pipes between them, and checkpoints that decide what flows.

Valves and interlocks control what flows where.→Login checks and permissions are drawn as valves, so a missing one is a visible gap.
RevelCode declares expected states and runtime checks.→Rules in plain English: "only Maya can see Maya's habits." Checked on every change.

The product

Four views of one app

Map

The whole system on one sheet

Generated from the code, never drawn by hand. Grouped the way a person thinks: what users see, your server, stored data, outside services.

Explain

Every part in a sentence

Click anything for what it does, what it talks to and where it lives in the code. Written for the builder, with the jargon taken out.

Trace

Follow one person through it

Play "someone signs up" and watch the request travel pipe by pipe, narrated step by step. This is how the system clicks.

Watch

See what the AI just changed

After every agent session, the drawing shows the new parts and pipes in a diff, and flags any rule that broke.
